# TypeSwitcher 1.1.31 → Switchcraft

Досліджено локальну теку `TypeSwitcher` (Windows x64). Джерела доказів: version resources EXE, PE imports/exports, рядки EXE, дизасемблювання обгорток C ABI, JSON-правила й ізольовані виклики через Python ctypes. Декомпіляція всього Swift-ядра не виконувалася. Оригінальні бінарні файли не патчилися.

## Архітектура оригіналу

`TypeSwitcher.exe` — нативна Win32-оболонка: низькорівневий хук клавіатури, SendInput, буфер обміну, меню трея, hotkeys, GDI, WinSparkle. `TypeSwitcherCABI.dll` — Swift-ядро з Foundation і власним правиловим/словниковим ранжуванням. У правилах 46 306 англійських, 48 483 російських і 44 666 українських словникових одиниць, разом 139 455. Кореневі секції включають розкладки, оцінювання, захищені шаблони, ручні заміни та 58 golden tests.

## Відновлені сигнатури Windows x64 C ABI

```c
void* ts_engine_create(const char* rules_path_utf8, const char* preferences_path_utf8);
char* ts_engine_evaluate(void* engine, const char* token_utf8, const char* input_source_utf8,
    int* changed, double* confidence,
    char* target_language, int target_capacity,
    char* reason, int reason_capacity);
char* ts_engine_convert_selection(void* engine, const char* text_utf8,
    const char* input_source_utf8, char* target_language, int target_capacity);
char* ts_engine_convert_selection_to(void* engine, const char* text_utf8,
    const char* target_language_utf8, char* target_language, int target_capacity);
void ts_free_string(char* string);
void ts_engine_destroy(void* engine);
```

`create` приймає **шляхи до файлів**, а не JSON-рядки. Перевірено через імпорт `FileManager` та експериментальний виклик. Рядки UTF-8, повернуті покажчики звільняються `ts_free_string`. `evaluate` може повертати порожній рядок, коли `changed == 0`; оболонка в такому разі зберігає оригінал. Для деяких seed-пар target_language порожня, тому оболонка визначає ціль за результатом/пріоритетом мов.

## Перевірена сумісність

Прямий виклик оригінального ядра збігся з 56/58 вбудованих фікстур. Дві розбіжності: `cfqns` із `session_language=uk` / `ru`. C ABI не має параметра session language й повертає `ambiguous_target`; Switchcraft відтворює фактичну поведінку цього ABI, а не підміняє її очікуванням старої фікстури. `research/native-results.json` зберігає як початкові очікування, так і фактичні результати.

Додаткові тести перевіряють застосування нових правил без перезапуску, власні слова-винятки, атомарну відмову некоректного імпорту, збереження налаштувань, формат INPUT x64, ручне перетворення та поліпшене поводження з пунктуацією. Інтеграційний тест проходить через справжні Windows keyboard hooks, окреме тестове поле, SendInput, clipboard та RegisterHotKey. Із версії 1.0.1 звичайний застосунок приймає зовнішній інжектований ввід, зокрема Unicode-пакети, а власні вставлення відсіює за dwExtraInfo. Тест використовує ту саму політику; єдиний тестовий виняток дозволяє обробку власного тестового вікна.

### Виправлення Notepad++ у версії 1.0.1

На цьому ПК редактор Notepad++ представлений в UI Automation як Pane, без текстового шаблону. Попередня перевірка Edit / Document / ComboBox помилково блокувала його. Додано вузьку перевірку нативного класу Scintilla: фокус у тому самому процесі, увімкнене поле, успішна відповідь SCI_GETREADONLY і доступність запису. Запит має тайм-аут 100 мс; інші нестандартні поля автоматично не дозволяються.

Джерела інтерфейсів: [Scintilla: SCI_GETREADONLY](https://scintilla.org/ScintillaDoc.html#SCI_SETREADONLY), [Microsoft: KEYBDINPUT і VK_PACKET](https://learn.microsoft.com/windows/win32/api/winuser/ns-winuser-keybdinput). Результати живої перевірки Notepad++ записані у `tests/notepadpp-results.json`.

## Свідомі відмінності

### Перемикання УК / RU у версії 1.0.2

Вихідний ABI повертав порожню цільову мову для `exact_seed_pair`, зокрема `ghbdtn` → `привет`. Оболонка раніше підставляла першу кириличну мову з налаштувань — українську. Тепер ціль визначається за окремими мовними словниками та `exact_pairs_meta.dst`; невідомій мові не призначається довільний пріоритет.

В оригінальних `common_words` є російські слова в українському наборі, а рідкісні словоформи й географічні назви відсутні. Для перевірки кириличних кандидатів додано незмінені Hunspell-словники LibreOffice (УК: 350658 кореневих записів, RU: 146269) та WeCantSpell.Hunspell 7.0.1. Перевірка включає афікси. Точні джерела, ліцензії й контрольні суми — `src/Dictionaries/NOTICE.md` і `research/language-data-manifest.json`.

Виправлення залишається зіставленням клавіш: довільні пропозиції орфографічного виправлення не використовуються. Коли оригінал і результат є правильними словами різних мов (наприклад, `косматій` / `косматый`), потрібні дві попередні однозначні мовні ознаки. Зберігаються тільки мітка мови, сила доказів та лічильник невизначених слів; попередні слова не записуються. Контекст скидається при навігації, зміні поля, абзаці, ручному перемиканні та після семи нерозпізнаних слів. Дві однозначні ознаки також можуть виправити УК / RU розкладку без переписування тексту.

Нові регресійні перевірки містять обидві фрази користувача, коректний український контекст, зворотний напрямок, пунктуацію, регістр, вимкнену мову, винятки й скидання контексту. Підсумок: 106 перевірок ядра й 25 інтеграційних перевірок Windows-вводу.

- Нова українська WPF-оболонка та власний значок Switchcraft.
- Окремі налаштування й правила в LocalAppData/Switchcraft.
- Упевнене автоматичне виправлення на пробілі/Enter/Tab; розділові клавіші всередині слова зберігаються для аналізу цілого токена.
- Власні правила можна додавати та імпортувати з інтерфейсу.
- Збереження пунктуації під час ручного перетворення за словниковою перевіркою.
- Нові редактор, жива перевірка, статистика та історія в пам’яті.
- Відсутні серверне надсилання відгуків, перевірка оновлень оригіналу та debug-log вводу.
- Мовна логіка лишається бінарною залежністю, вихідний код ядра не відновлено.

Файли оригіналу та їх SHA-256 наведено в `original-manifest.json`.
