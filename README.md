# Switchcraft

Windows-застосунок для автоматичного виправлення розкладки з темним українським інтерфейсом.

## Запуск

Інсталятор: `dist\Switchcraft-Setup-1.6.0-win-x64.exe`. Він встановлює програму для поточного користувача, створює ярлики та запис у списку встановлених програм Windows. Права адміністратора й окреме встановлення .NET не потрібні. Новішу встановлену версію інсталятор не понижує; під час оновлення або видалення Switchcraft потрібно завершити через меню значка в треї. Особисті налаштування та правила зберігаються після видалення.

Компонент інсталятора **Локальна модель Laya** вибраний, якщо Laya ще не підготовлена. Після натискання «Готово» Switchcraft відкриває налаштування Laya, вмикає режим «Laya · локально» й завантажує модель r3 та компоненти з прогресом і можливістю скасувати. Підготовку виконує сама програма (див. розділ про Laya), тому інсталятор не завантажує нічого сам і не потребує прав адміністратора. Якщо Laya вже підготовлена, компонент недоступний. Для тихого встановлення з Laya: `Switchcraft-Setup-1.6.0-win-x64.exe /S /LAYA`; без `/LAYA` тихе встановлення Laya не запускає.

Відкрийте `dist\Switchcraft\Switchcraft.exe` або ярлик `Switchcraft.lnk` у корені цієї теки. Тримайте теки `Runtime` і `Dictionaries` поруч із виконуваним файлом. Готова автономна збірка містить .NET; встановлювати середовище виконання окремо не потрібно.

Після закриття вікна Switchcraft залишається в треї. Щоб завершити роботу, виберіть **Вийти** в меню значка або **Вийти з програми** в налаштуваннях. Автозапуск вимкнено за замовчуванням. Одночасно запускайте один перемикач розкладки: якщо під час старту виявлено TypeSwitcher, Switchcraft починає з паузи.

## Можливості

- Автоматичне виправлення EN / УК / RU після пробілу, зі збереженням регістру. У Scintilla підтримується також Enter. В інших полях Enter і Tab проходять без повторного введення, щоб уникнути повторного надсилання форми або зайвого переносу рядка.
- Розширена перевірка українських і російських словоформ та назв за локальними Hunspell-словниками. `Кіргізстан` → `Кыргызстан`, `свыт` → `світ`.
- Для неоднозначних українсько-російських слів враховуються останні однозначно розпізнані слова: у російській фразі `косматій` → `косматый`, а в українській `у косматій шапці` зберігається. У режимі словників контекст містить лише мітки мов і скидається при переході до іншого поля, новому абзаці, навігації та ручному перемиканні розкладки. Без достатнього контексту правильне словникове слово не переписується.
- Після трьох однозначних слів розкладка УК / RU може виправлятися навіть без заміни літер. Контекст слабшає після паузи, скидається на межі речення й цитати; власні виправлення програми його не підсилюють.
- Підтримка редактора Notepad++ / Scintilla, зокрема коли він не надає текстового інтерфейсу UI Automation. Зовнішні клавіатурні події від засобів віддаленого доступу обробляються; власні заміни Switchcraft повторно не перехоплюються.
- Перетворення виділеного тексту, зокрема на конкретну мову.
- Перемикання системної розкладки після виправлення, якщо вона встановлена у Windows.
- Безпечне скасування останньої автоматичної заміни після пробілу: новий ввід, навігація, клік або зміна поля скидають можливість скасування.
- Пауза до відновлення та пауза на 15 хвилин.
- Мови та їх порядок, програми-винятки, редагування гарячих клавіш із виявленням конфліктів.
- Пошук, додавання і видалення власних замін та слів-винятків; імпорт/експорт JSON.
- Режим навчання: скасоване слово додається до винятків.
- Жива перевірка слова, окремий редактор для тексту, лічильник виправлень і необов’язкова історія сесії.
- Обережний режим зберігає правильні словникові слова навіть за суперечливого мовного контексту. У збалансованому режимі сильний контекст може розв’язувати неоднозначність між УК та RU.
- Збереження кінцевих розділових знаків у ручному перетворенні, коли словник розпізнає основу слова. Наприклад, `Ghbdsn, cdsnt!` → `Привіт, світе!`. Клавіші-літери на кшталт крапки в `dsltkz.` → `выделяю` зберігають правильне зіставлення.

## Локальна модель Laya (1.6.0)

У **Налаштуваннях → Як визначати мову** доступні три окремі режими: **Словники**, **TypeSafe AI**, **Laya · локально**. Для Laya стандартна тека моделі — `%LOCALAPPDATA%\Switchcraft\Laya\model`. Шлях можна змінити та перевірити кнопкою **Перевірити модель**. Ключ TypeSafe для цього режиму не потрібен і залишається збереженим для повернення до хмарного режиму.

На новому ПК підготуйте Laya компонентом інсталятора або кнопкою **Завантажити й підготувати** в цьому розділі. Якщо вибрати режим Laya, коли вона ще не встановлена, програма покаже це й запропонує кнопку. Switchcraft бере модель r3 (приблизно 600 МБ) з [релізу GitHub](https://github.com/phantasmat2018/Switchcraft-AI/releases/tag/laya-r3), перевіряє SHA-256 і встановлює окремий Python 3.12 та залежності для поточного користувача. Окремо встановлювати Python, Visual C++ Runtime або .NET не потрібно. Перерване завантаження можна продовжити, а наявна модель не перезаписується; після успішної підготовки завантажені архіви видаляються. Хід і помилки підготовки записуються в `%LOCALAPPDATA%\Switchcraft\Laya\setup-progress.log` (без набраного тексту). Інтернет потрібен для цієї підготовки; саме ввімкнення режиму нічого не завантажує.

Доступні **Автоматично**, **CPU** та **NVIDIA CUDA**. Пакет прискорення обирається лише для сумісної карти й драйвера; інші GPU використовують CPU. Перевірка доступності CUDA включає виконання операції на GPU, а статус показує фактичний пристрій. За замовчуванням CPU використовує половину логічних процесорів, не більше чотирьох потоків. Одночасно обробляється лише один запит; час очікування CPU адаптується в межах 1,6–3 с. Скасовані й застарілі результати не змінюють новий текст.

Перед завантаженням у пам’ять потрібно близько 2 ГБ вільної RAM. На слабкому або зайнятому ПК доступні словники, які не потребують моделі. Laya завантажується у фоновому процесі; її сервер слухає лише `127.0.0.1` та потребує випадкового ключа поточного запуску. Поки модель завантажується, не відповідає або не впевнена, працює словниковий резерв. Перехід до іншого режиму скасовує очікування й завершує лише процес моделі, запущений цим екземпляром Switchcraft. Локальний режим ніколи автоматично не переходить до TypeSafe.

Для кожного сумнівного слова формується питання `wN` з його фактичним номером у короткому контексті та поточними прочитаннями EN / УК / RU. Модель обирає лише серед механічних варіантів розкладки; Switchcraft додатково перевіряє словник, увімкнені мови, фокус і текст. Ймовірності однакових прочитань підсумовуються. Мовна мітка сама по собі не є підставою змінювати написання або перемикати неоднозначну розкладку. Захист правильних слів, абревіатур, технічних токенів і згадок окремих літер спільний із режимом TypeSafe.

Наявна модель — mmBERT / Laya 0.4.1. Її навчальний звіт містить перетини навчальних і перевірочних прикладів, тому наведена в ньому точність не є незалежною оцінкою. Початковий генератор навчального `state` не входить до експорту; адаптер Switchcraft перевіряється окремо на синтетичних тримовних прикладах. Інсталятор програми не містить великих ваг і Python-середовища: вони зберігаються окремо у теці Laya та залишаються після видалення застосунку.

Перевірка 1.6.0: 339 автоматичних перевірок, зокрема 45 для встановлення та профілів обладнання; 10/10 перевірок справжнього вводу з локальною моделлю. Ваші приклади `Червоний ы зелений`, `Былий і чорний`, `ой чий то кінь стоъть` виправлено саме рішеннями Laya. На одному CPU-потоці контрольний корпус дав 50/50 з паузою 600 мс між незалежними прикладами; серія без пауз дала 49/50 — одна неоднозначна заміна була пропущена через обмеження частоти. Це не оцінка загальної точності або гарантія виправлення кожного слова при швидкому наборі. Звіти: `tests/release-engine-1.6.0.json`, `tests/release-laya-input-1.6.0.json`, `tests/laya-one-thread-paced-results.json`, `tests/laya-one-thread-results.json`. Повне встановлення перевірено на чистій Windows (Windows Sandbox без Visual C++ Redistributable і Python, профіль `C:\Users\Олександр Тест`): `Setup.exe /S /LAYA` → підготовка Laya за 3,3 хв → 10/10 перевірок справжнього вводу з Laya. Ця перевірка виявила й закрила дві вади: PyTorch не завантажувався без Visual C++ Redistributable, а шлях профілю з пробілом зупиняв встановлення компонентів. Звіти: `tests/release-cleanpc-*.json`, `tests/release-cleanpc-1.6.0.log`. У Sandbox захист Defender у реальному часі був вимкнений. Реальне CUDA-прискорення ще потребує окремої перевірки.

## Режим TypeSafe AI (1.3.0)

Логіка EN / УК / RU у версії 1.3.0:

- Поточна розкладка Windows є підказкою. Варіанти будуються для всіх увімкнених мов, проходять словникову перевірку; однакове написання двома мовами надсилається одним варіантом. Для спільного слова на кшталт `собака` розкладка не обирається навмання.
- Правильні англійські слова, короткі латинські абревіатури на кшталт RGB / VNC й звичайні українські/російські слова зберігаються без API. Для словниково правильного УК/RU слова з альтернативним закінченням потрібні щонайменше два однозначні сусідні слова іншою мовою, відсутність суперечливих сусідів і впевнене рішення AI. Невпевненість чи недоступність API зберігає оригінал.
- Для невідомого слова однозначний словниково перевірений варіант залишається локальним резервом. Дужки, регістр і пунктуація зберігаються; клавіші `[`, `]`, `;` тощо можуть бути частинами слова іншою розкладкою. AI не перекладає і не виконує довільне виправлення орфографії.
- Черга зберігає до чотирьох завершених слів для повторної перевірки. Кожне може отримати до трьох наступних слів контексту. Це дозволяє виправити кілька помилок у безперервному наборі. Виправлення попереднього слова не перемикає розкладку поточного; недописане слово залишається лише контекстом.
- Межі речень, цитат, зміна поля, навігація та ручне перемикання скидають відповідний контекст. Кожна заміна окремо перевіряє текст, курсор і фокус. Скасування повертає тільки останню фактично застосовану заміну.
- У Notepad++ список автодоповнення більше не скидає накопичене слово: його віртуальний фокус відрізняється від справжнього переходу до іншого поля. Перевірено фізичний набір `руддщ` → `hello`, `ghbdtn` → `привет`, `стоъть` → `стоїть`.

Сувора перевірка словником може пропускати рідкісні назви й словоформи, яких у словниках немає. Неоднозначні правильні слова за слабкої відповіді AI залишаються без змін. Корпус із 50 різномовних прикладів і результати реального API: `tests/typesafe-trilingual-fixtures.json`, `tests/typesafe-trilingual-results.json`. Це контрольні приклади, а не оцінка точності на всіх текстах.

У **Налаштуваннях → Як визначати мову** оберіть **TypeSafe AI**. Перехід до **Словників** або **Laya · локально** скасовує очікування API; вибір зберігається після перезапуску. Для нових налаштувань за замовчуванням обрані словники.

Після ввімкнення вставте власний ключ, залиште модель `jev-latest` (або вкажіть доступну вашому обліковому запису), натисніть **Зберегти підключення**, потім **Перевірити API**. Перевірка надсилає лише синтетичне слово `ghbdsn`. Офіційний протокол: [TypeSafe API](https://docs.typesafe.ai/api), `POST https://api.typesafe.ai/v1/systemone`, Bearer, питання Choice.

TypeSafe вибирає між локально сформованими варіантами EN / УК / RU та «залишити без змін». Відповідь не може містити довільну заміну: Switchcraft застосовує тільки власне перетворення розкладки. За низької впевненості локальний резерв виправляє однозначні словникові помилки, а правильні неоднозначні слова зберігаються; впевнена відповідь «залишити» зберігає оригінал; власні правила, слова-винятки, захищені поля та виключені застосунки мають пріоритет. API використовується під час автоматичного виправлення та живої перевірки слова. Ручне перетворення виділення і сторінка «Перетворення» залишаються локальними.

Передається поточне слово (до 80 символів), локальні варіанти й до 6 попередніх слів (не більше 180 символів), зібраних під час набору в дозволеному полі. Для повторної перевірки завершеного слова також можуть передаватися до 3 наступних слів (разом не більше 160 символів); останнє з них може бути ще недописаним. Воно використовується лише як контекст. Повний документ не читається для API. Email, шляхи й технічні токени відсіюються, але це не універсальний фільтр конфіденційних даних: для приватного тексту вимкніть режим або додайте застосунок до винятків. Текст запитів і ключ не записуються в діагностику. Ключ зберігається окремо в `typesafe-key.dat`, зашифрований DPAPI для поточного користувача Windows, і не входить до експорту правил.

Очікування після пробілу — 120 мс; граничний час запиту — 1,2 с. Нове введення або зміна фокусу скасовує стару відповідь. За швидкого безперервного набору AI може пропускати виправлення. Під час помилок, таймаутів або відсутності ключа працює локальний рушій з описаними вище обмеженнями. Один активний запит, до 60 запитів/хв, обмежений кеш у пам’яті, пауза після 401/429/помилок сервера. Протокол перевірено на імітованих відповідях та окремому корпусі синтетичних прикладів реального API. Це контрольні приклади, а не оцінка загальної точності; точність і затримка залежать від TypeSafe.

У версії 1.2.2 короткі слова перевіряються з контекстом, який зберігається навіть після скасування запиту новим вводом. Для `Червоний ы зелений` окреме `ы` повторно перевіряється після пробілу за наступним словом; перед заміною звіряється весь кінцевий фрагмент і позиція курсора. Український контекст допомагає локальному резервному правилу, коли AI не впевнений. Згадки на кшталт `буква ы`, цитована літера, правильні `і` та `и` зберігаються. Це не загальне правило заміни кожного `ы`. Перевірено набір через справжній клавіатурний перехоплювач з імітованими відповідями та з реальним TypeSafe: `tests/ai-short-input-results.json`, `tests/ai-short-live-input.json`.

У версії 1.2.3 повторна перевірка охоплює також слова зі словниковим виправленням: `Былий і чорний` → `Білий і чорний`. Незастосована заміна може дочекатися до трьох наступних слів, не довше 15 секунд. Якщо ви зупинилися без кінцевого пробілу, після 450 мс паузи запускається перевірка раніше завершеного слова. Поточне недописане слово не виправляється. Відповідь застосовується лише за збігу кінцевого фрагмента, фокусу й курсора; новий ввід скасовує запит. Скасування такої заміни зберігає всі наступні слова та не додає зайвого пробілу. Звіти цільових перевірок: `tests/context-input-results.json`, `tests/ai-context-regression.json`.

## Дані та обмеження

Налаштування зберігаються в `%LOCALAPPDATA%\Switchcraft`: `settings.json`, `user_preferences.json`, `typeswitcher_rules.json`. Оригінальна тека TypeSwitcher не змінюється. Запис налаштувань атомарний; перед імпортом правил створюється резервна копія. У локальному режимі програма не робить мережевих запитів. TypeSafe AI вмикається окремо в налаштуваннях і передає короткий фрагмент тексту до API. Історія містить максимум 50 виправлень, зберігається лише в оперативній пам’яті й очищується після виходу або вимкнення історії.

Поля паролів, про які повідомляє Windows UI Automation, та відомі менеджери паролів пропускаються. Для Scintilla окремо перевіряється, що фокус належить увімкненому редактору поточного застосунку, документ доступний для запису й редактор відповідає. Якщо тип іншого поля визначити неможливо, автоматичне виправлення не виконується. Власний редактор Switchcraft не перехоплює набір. Шляхи, електронні адреси та URL мають додатковий захист від автозамін.

Застосунки, запущені з вищими привілеями, можуть блокувати вставлення. Ігри, нестандартні редактори, IME та програми без доступного текстового поля можуть не підтримувати автозаміну. У такому випадку скористайтеся вбудованим редактором або додайте програму до винятків. Невідомі розкладки не обробляються. Виділення до 100 000 символів; поточне слово до 256. Тестування на всіх сторонніх застосунках не проводилося.

## Що відтворено

Нові вихідні тексти C# / WPF реалізують оболонку, трей, клавіатурні й мишачі перехоплювачі, буфер обміну, налаштування та весь інтерфейс. Мовне ядро **не декомпільоване у відновлений Swift-код**: використовується локальна `TypeSwitcherCABI.dll` та її словники. Інтерфейс C ABI відновлено аналізом PE і перевірено викликами. Докладніше: `research/REVERSE-ENGINEERING.md`.

Сервіси оновлення TypeSwitcher, надсилання відгуків розробнику оригіналу та журналювання сирого вводу не підключені. Інтерфейс Switchcraft український. Автоматичні неоднозначні слова зберігають консервативну поведінку доступного ядра; дві старі контрольні фікстури з `session_language` не можна відтворити через його поточний C ABI.

## Збірка й перевірка

У версії 1.1.0 кандидати EN → УК / RU перевіряються повними словниками. Вбудовані підказки не переважають правильне слово (`руку` зберігається); явно додані користувачем правила мають окремий пріоритет. Назви з малої літери та канонічно еквівалентні Unicode-послідовності також розпізнаються.

Мовний аналіз виконується поза клавіатурним перехоплювачем. Черга обмежена, результати зі старою послідовністю вводу скасовуються. Перед заміною перевіряються фактичний текст, виділення, фокус і позиція курсора; для Scintilla — також документ, кодування, множинні курсори й віртуальний простір. Вставлення та скасування підтверджуються читанням результату. Операції перетворення виконуються послідовно. Scintilla використовує пряме введення; інші підтримувані поля — вставлення через буфер із відновленням усіх збережених форматів після підтвердження результату. Нове копіювання користувача має пріоритет. Для тимчасового тексту встановлюються заборони історії й хмарної синхронізації буфера. Якщо результат вставлення не підтверджений, програма повідомляє про це й залишає виправлення в буфері замість передчасного відновлення. Зайнятий буфер має обмежені повторні спроби; його окремий STA-потік не блокує інтерфейс.

UI Automation працює на окремому MTA-потоці з обмеженням часу очікування; недоступний текстовий провайдер вимикає виправлення в цьому полі. При швидкому наборі непідтверджене виправлення може бути пропущене. У полях, де Enter надсилає повідомлення, вже надісланий текст не змінюється.

Повторюваний аудит точності:

```powershell
dotnet run --project tools/accuracy-audit/AccuracyAudit.csproj -c Release -- tests/accuracy-audit-1.1.0.json
```

Це синтетична словникова вибірка, а не оцінка точності на всіх реальних текстах. Звіти містять окремі результати для пропущених виправлень, хибних замін, правильних слів, змін мовного контексту та обережного режиму.

Потрібен Windows x64 та .NET SDK 8. Оригінальні DLL і правила мають бути в `TypeSwitcher` поруч із `src`.

```powershell
./tools/build.ps1 -SelfContained
./tools/test.ps1
./tools/test.ps1 -InputIntegration
```

Після перевіреної автономної збірки інсталятор створюється командою `./tools/build-installer.ps1` (NSIS 3.10). Сценарій звіряє виконуваний файл із маніфестом перевіреної версії. Параметр `-TestBuild` створює пакет із відокремленим реєстраційним ключем та тестовими ярликами для перевірки встановлення й видалення без зміни наявної інсталяції. Інсталятор підтримує `/S`, `/LAYA` (підготувати Laya після тихого встановлення) і стандартний параметр NSIS `/D=шлях` наприкінці командного рядка; деінсталятор підтримує `/S`. Тестова збірка ніколи не запускає програму після встановлення. Сценарії збирання й перевірки інсталятора працюють у Windows PowerShell 5.1.

Інтеграційний тест відкриває тимчасове тестове вікно й друкує лише тестові фрази. На час цього тесту завершіть звичайний Switchcraft та не перемикайте фокус. Якщо Windows не активувала тестове вікно автоматично, активуйте його протягом 30 секунд. Тест припиняється при втраті фокусу, щоб не вводити текст у сторонні програми. Перевіряються також російська автозаміна зі звичайних зовнішніх SendInput-подій і Unicode-пакетів та ігнорування власних вставлень. Звіти: `tests/engine-results.json`, `tests/input-results.json`.

## Файли проєкту

- `src/` — редаговані вихідні тексти нового застосунку.
- `tools/` — збірка, тести, ізольований аналіз оригінального C ABI.
- `research/` — результати аналізу, контрольні приклади та опис сумісності.
- `dist/Switchcraft/` — готова збірка.
